# Player fire is a visual class outside the threat palette, escalating by mass not hue

The player's shot is its own visual class — **white/pale-gold**, deliberately *outside* the blue/orange/purple threat palette — and **Guns tier** escalates it by the *amount* of fire (count, size, brightness), never by shifting its hue. This amends [[0001-projectile-colour-by-threat-tier]], which framed the player shot as "yellow/white," i.e. a fourth slice of the same colour wheel. The reframe: the threat palette is an **enemy-fire dodge language** the player *reads* (how do I evade this?); player fire answers a different question (*is this mine?*) and so lives in a separate register entirely.

Two independent signals ride the player shot, on orthogonal axes:

- **Hue = ownership.** White/pale-gold means "mine," fixed forever. This is the signal that must never wobble — it's what keeps ownership unambiguous in a dense pattern, the original intent of ADR-0001.
- **Mass = power.** [[0007-hangar-four-stat-tracks-plus-gadget-loadout]]'s Guns tier escalates fire through count/size/brightness — tier 0 a single thin tracer, tier 3 a fat multi-stream. The player reads "I got stronger" from the *volume* of fire, not by decoding a colour. This is already implied by Guns tier driving projectile count in [[CONTEXT]]; this ADR just forbids expressing it as a hue shift.

The hard rule that falls out: the player register may brighten and grow but **must never drift toward the aimed orange**. A white→amber→orange "hotter = stronger" ramp would collide the player's own fire with the aimed-threat tier — the one direction tier escalation cannot go. Anchor white/pale-gold; escalate by getting brighter and bigger.

We considered **sourcing/authoring a true yellow player tracer** (the literal ADR-0001 reading) — rejected as a blank-canvas instinct now that the project is asset-driven: the pill sprites already carry a bright white core, so a white/pale-gold player tracer is a `modulate` away with no new art. We considered **letting the player shot signal Guns tier through hue** (tier 0 white → tier 3 hot) — rejected because every "hotter" direction runs into a threat colour, and tier is better felt through mass anyway. We considered **green/white** for maximum distinction from all three threat hues — kept as a fallback if white/pale-gold ever reads too close to orange in play, but passed over for now because the WWII tracer feel is worth keeping and the white core already disambiguates.

Consequence: blue/orange/purple is **enemy-only**; nothing the player fires ever borrows a threat hue. Pattern-tier (purple) stays boss/elite-gated per [[CONTEXT]] — the disposable prototype's spread-firing grunts (Interceptor/AceFighter/Bomber) are not carried into the locked archetype taxonomy, so no common enemy fires purple. Deferred, not solved: purple is the one threat hue with colour-blind risk (blue/purple confusion), but the common-case blue-straight vs orange-aimed pair is already a colour-blind-safe contrast; and all projectiles currently share one pill shape (colour-only encoding) — shape-redundancy and an alternate-palette toggle are the proper accessibility upgrades, parked with PRD-02's deferred colour-blind work and acknowledged as likely a future-project concern.
