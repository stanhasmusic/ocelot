# SFX are organised by weapon class, not by threat tier

Enemy-fire sound effects map to **weapon class** — light MG, heavy cannon, AA flak, missile, panzer cannon, etc. — and reflect the actual weapon the asset depicts. They do **not** mirror the threat-tier colour language locked by [[0001-projectile-colour-by-threat-tier]] and amended by [[0012-player-fire-is-a-visual-class-outside-the-threat-palette]]. A tank cannon and a fighter MG that both fire aimed-tier (orange) projectiles will sound **completely different** — the visual signal carries the dodge teaching; the sonic signal carries the WWII fiction.

The surprising-to-future-readers piece: there is a **near-parallel "SFX by threat tier" design** that any audio designer would consider first — pellet sound for blue/straight, brass-shell for orange/aimed, swelling pad for purple/pattern. It would double-stamp the threat language across two senses (eyes + ears) and accelerate the noob/mid-tier audience's learning loop ([[0013-invisible-onboarding-no-tutorial]]). We rejected it for two reasons working together: (1) **the SFX library is already diegetic** — `assets/audio/Sound Effects/` ships with `browning`, `pnzrfire`, `AAfire`, `kblwgnngn2`, `t34eng`, `mp18mlp` and many more weapon-specific assets, voted into existence by the asset-driven approach ([[project-design-direction]]); collapsing them into 3 generic tier sounds throws that variety away. (2) **The threat language is already redundant in the visual channel** — projectile colour, plus the eventual shape-redundancy upgrade flagged in [[0012-player-fire-is-a-visual-class-outside-the-threat-palette]], is enough to teach blue-vs-orange-vs-purple; adding a third audio redundancy is over-teaching at the cost of WWII immersion.

We considered the **hybrid** — threat tier sets pitch/intensity, weapon class sets timbre — and rejected it as over-engineered for a mobile shmup: it asks the composer to tune two orthogonal axes per SFX, and it asks the player to deconvolve them in real time, when neither problem actually exists.

Consequences worth stating: (1) The full SFX-event-to-asset mapping is **curation work** the user owns ([[user-learning-exercise]] — taste calls live with him), and the asset library is rich enough that nearly every event already has a candidate sound; PRD-16 enumerates the event taxonomy but does not pre-assign asset paths. (2) The **threat-tier colour language remains the sole canonical channel for dodge teaching** — [[0013-invisible-onboarding-no-tutorial]]'s blue-vs-orange teaching still rides entirely on the colour signal, with shape-redundancy as the eventual accessibility path. SFX is explicitly *not* part of that teaching loop. (3) **Player fire is the one exception worth noting**: per [[0007-hangar-four-stat-tracks-plus-gadget-loadout]] Guns tier, the player's gun SFX is planned to escalate across tiers 0–3 with distinct sounds, so the upgrade is *audibly* re-experienced on every shot. This is a slight tension with the "SFX is not part of teaching" principle (the SFX *does* signal a player axis), but the axis here is "my power level" not "what tier of threat" — the colour-language overlap doesn't apply. The final A-vs-B call (4 distinct sounds vs 1 shared sound) is a playtest sign-off the user owns.
