# Onboarding is invisible scenario-teaching plus self-suppressing hints — no tutorial, no first-run state

The first-time-user experience teaches move / fire / bomb and the threat-tier colour language through **the design of Level 1's first stage intro**, reinforced by a thin layer of **contextual hints that trigger on player failure and suppress themselves on success**. There is **no separate tutorial level, no modal walkthrough, and no "first launch ever" flag** anywhere in the save data. This is the make-or-break system for the noob/mid-tier audience ([[project-ocelot-target-audience]]), so the bias throughout is "teach without the player noticing they're being taught."

The teaching splits into two layers that behave differently on replay:

- **The scenario onramp (permanent).** *Which* enemies spawn, in what order, in the Level-1 Stage-1 **stage intro** ([[0002-hybrid-stage-difficulty]]) — a lone blue **Straight-tier** Strafer first so "step aside" is self-evident, then an orange **Aimed-tier** shot so standing still is punished, then a survivable swarm that begs for a **Bomb**. This is just good level design; it is invisible-as-teaching, never blocks play, and runs every **Playthrough**. It is *not* a tutorial, so it does not violate the arcade "jump in and play" feel, and a returning player never resents it.
- **The self-suppressing hint layer (behavioural).** Prompts fire only when the player demonstrably needs them: "DRAG TO MOVE" fades in only if the player hasn't moved in the first ~2s; the "keep moving — orange aims at you" hint fires only if the player eats an Aimed-tier shot while standing still; the on-screen **Bomb** button (the "PUSH TO JETT" red dome) pulses the first time a bomb-worthy swarm appears. A player who just plays competently never sees any of it.

The pivotal consequence — and the reason this is recorded — is that **competence is the suppression signal, so no persistent "have I onboarded" state is needed.** That sidesteps a real tension with [[0005-persistent-campaign-with-hangar-metagame]] (amended by [[0011-economy-guns-spine-scarce-skill-fed-slack]]): **New Game** resets a Playthrough to zero and the campaign is replayed from scratch, so any onboarding flag stored *in* the Playthrough save would replay the tutorial every New Game (the forced-every-Playthrough outcome we explicitly rejected), while a flag stored *outside* it adds device-level state that can misfire (a player who bounced a year ago returns to no hints). Behavioural triggers need neither.

We considered a **dedicated tutorial sequence** before Level 1 (a no-stakes sandbox drilling move → fire → bomb → colours) — rejected because it duplicates Level 1's job, is throwaway scope a solo learner shouldn't carry ([[user-learning-exercise]]), and breaks the arcade jump-in feel by gating play. We considered **modal popups/tooltips over normal play** — rejected as the manual-in-disguise the "learn without reading a manual" acceptance criterion is trying to avoid. We considered an **explicit first-launch-only flag** showing full callouts once ever — rejected for the persistence/misfire problems above; behavioural self-suppression gets the same "veterans aren't nagged" outcome with no stored state.

Consequences worth stating: (1) FTUE owns **no new difficulty machinery** — "early difficulty eases newcomers in" is satisfied by the Level-1 tier-0 onramp ([[0010-absolute-difficulty-curve-with-hangar-catchup]]) plus an authoring spec for the L1S1 intro timeline (implemented in the Level-1 content PRD, not the FTUE PRD). (2) FTUE owns **no glyph logic** — every hint is phrased through the active control scheme published by [[0006-input-aware-controls-shared-difficulty]] (so "DRAG TO MOVE" on touch/mouse, stick/key prompts on pad/kbd), and the touch control stays drag-to-move (the cockpit HUD's centre directional element is movement *feedback*, not a D-pad — reverting to a virtual D-pad would be a separate ADR amending 0006). (3) Only **blue (Straight) vs orange (Aimed)** are taught in the FTUE; **purple (Pattern)** is boss/Elite-gated and gets its own teaching moment in the City level, out of FTUE scope. (4) The whole approach leans on **hue discrimination**, which is the colour-blind/shape-redundancy gap deferred in [[0012-player-fire-is-a-visual-class-outside-the-threat-palette]] — acknowledged, not solved. (5) The "validated with a non-gamer" criterion is **gated on a real phone build** and so couples to the mobile-reach PRD ([[project-playtest-setup]]): a PC mouse-proxy pass validates teaching *logic*, but touch *feel + comprehension* sign-off waits for a device.
